# Ringkasan Proyek: Platform Flash Sale dan Tiket Event

### Situation
Penjualan tiket konser dan flash sale sering menghadapi lonjakan trafik masif (thundering herd) pada detik pertama loket dibuka. Arsitektur transaksi konvensional kerap mengalami kelambatan parah, transaksi macet di tengah jalan, dan masalah paling merugikan yaitu kelebihan penjualan tiket melebihi kapasitas fisik (overselling) akibat perebutan data (race condition) pada basis data relasional. Kondisi ini merusak reputasi penyelenggara acara, mengecewakan pembeli yang telah membayar, dan menimbulkan beban operasional besar untuk menangani komplain serta pengembalian dana manual.

### Task
Tantangannya adalah merancang dan membangun platform tiket terdistribusi hulu ke hilir yang mampu menahan lonjakan ratusan permintaan per detik, menjamin konsistensi kuota dengan tingkat overselling tepat 0%, mencegah transaksi ganda akibat klik berulang, menyediakan ruang antrean tertib dengan pembaruan posisi real-time, mengintegrasikan alur pembayaran multi-metode, serta menerbitkan e-tiket digital berbarcode mandiri dengan jejak audit forensik lengkap.

### Action
Dibangun sistem berkinerja tinggi menggunakan Go, GraphQL (gqlgen), dan React 18 dengan arsitektur proteksi stok dua lapis. Pada lapisan pertama, skrip Lua atomik di Redis (DecrStockAtomic) mengeksekusi pemotongan kuota cepat di memori sebelum kueri menyentuh basis data. Lapisan kedua menerapkan klausa SQL relatif kondisional di PostgreSQL dengan mekanisme kompensasi rollback otomatis jika terjadi kegagalan. Alur transaksi dipisahkan menjadi jalur kritis dan sekunder, di mana pemrosesan lanjutan dialirkan ke antrean RabbitMQ dengan Dead-Letter Queue dan percobaan ulang bertahap (exponential backoff). Sistem dilengkapi ruang antrean virtual berbasis Redis Sorted Set dengan radar antrean langsung, token izin belanja sekali pakai (Single-Use Checkout Pass), kunci idempotensi (Idempotency-Key) untuk mencegah transaksi ganda, pekerja rekonsiliasi latar belakang dengan masa tenggang transaksi (in-flight grace period) dan pelepasan otomatis reservasi kedaluwarsa, simulator pembayaran Midtrans Snap, penerbitan e-tiket dengan barcode dan kode QR, serta dasbor analitik admin untuk pemantauan omset dan kontrol pelepasan antrean batch.

### Result
Pengujian beban ekstrem menggunakan k6 membuktikan sistem mempertahankan 0,00% tingkat galat HTTP dengan throughput hingga 138 transaksi per detik pada lonjakan beban hingga 300 pengguna serentak. Pada pengujian perebutan 100 tiket terbatas oleh 500 pengguna serentak dengan 2.000 percobaan transaksi, sistem berhasil menjual tepat 100 tiket dan menolak 1.900 permintaan lainnya secara tertib dengan sisa stok basis data tepat 0 dan tingkat overselling mutlak 0%. Seluruh pengujian otomatis, termasuk detektor kondisi balapan (Go race detector), pengujian integrasi kegagalan perantara, dan otomasi peramban Playwright, lulus tanpa ada kebocoran stok tiket.
